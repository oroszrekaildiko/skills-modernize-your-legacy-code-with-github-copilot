# COBOL Account Management Test Plan

Use this plan to validate the current COBOL behavior with business stakeholders before and during the Node.js migration. Leave **Actual Result**, **Status**, and **Comments** blank until each case is executed and reviewed.

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
|---|---|---|---|---|---|---|---|
| TC-001 | Start the account management application | Application is compiled and available to run | 1. Start the application. | The account management menu is displayed with options to view balance, credit account, debit account, and exit. |  |  |  |
| TC-002 | Verify the initial account balance | Fresh application process has started; no prior transaction has been performed | 1. Select `1` (View Balance). | The displayed current balance is `1000.00`. |  |  |  |
| TC-003 | View the current balance after no balance change | Application is running with the initial balance of `1000.00` | 1. Select `1` (View Balance). | The application displays `Current balance: 1000.00` and returns to the menu. |  |  |  |
| TC-004 | Credit the account with a positive amount | Application is running with balance `1000.00` | 1. Select `2` (Credit Account). 2. Enter `250.00`. | The application accepts the amount, displays a new balance of `1250.00`, and stores the updated balance. |  |  |  |
| TC-005 | Verify a credit persists when the balance is viewed | TC-004 completed successfully, or balance is otherwise `1250.00` | 1. Select `1` (View Balance). | The application displays `1250.00`, confirming that a successful credit was persisted. |  |  |  |
| TC-006 | Credit the account with a zero amount | Application is running with balance `1000.00` | 1. Select `2` (Credit Account). 2. Enter `0.00`. | The application accepts the amount, displays a new balance of `1000.00`, and does not change the stored balance. |  |  | Confirm with stakeholders whether zero-value credits should remain supported. |
| TC-007 | Perform multiple credits sequentially | Application is running with balance `1000.00` | 1. Select `2`; enter `100.00`. 2. Select `2`; enter `50.25`. 3. | TC-008 | Debit an amount less than the current balance | Application is running with balance `1000.00` | 1. Select `3` (Debit Account). 2. Enter `275.50`. | The application accepts the amount, displays a new balance of `724.50`, and stores the updated balance. |  |  |  |
| TC-009 | Debit the exact current balance | Application is running with balance `1000.00` | 1. Select `3` (Debit Account). 2. Enter `1000.00`. 3. Select `1`. | The debit succeeds, the new balance is `0.00`, and the later balance inquiry displays `0.00`. |  |  |  |
| TC-010 | Reject a debit greater than the current balance | Application is running with balance `1000.00` | 1. Select `3` (Debit Account). 2. Enter `1000.01`. 3. Select `1`. | The application displays `Insufficient funds for this debit.` The balance remains `1000.00`. |  |  |  |
| TC-011 | Confirm an unsuccessful debit is not persisted | Application is running with balance `1000.00` | 1. Select `3`; enter `1500.00`. 2. Select `1`. | The balance inquiry displays `1000.00`; no write occurs for the rejected debit. |  |  |  |
| TC-012 | Perform multiple debits sequentially | Application is running with balance `1000.00` | 1. Select `3`; enter `200.00`. 2. Select `3`; enter `300.50`. 3. Select `1`. | The first debit produces `800.00`; the second produces `499.50`; the final balance inquiry displays `499.50`. |  |  |  |
| TC-013 | Enter an invalid menu choice below the valid range | Application is running | 1. Enter `0` at the menu prompt. | The application displays `Invalid choice, please select 1-4.` and continues to display the menu. The balance is unchanged. |  |  |  |
| TC-014 | Enter an invalid menu choice above the valid range | Application is running | 1. Enter `5` at the menu prompt. | The application displays `Invalid choice, please select 1-4.` and continues to display the menu. The balance is unchanged. |  |  |  |
| TC-015 | Exit the application | Application is running | 1. Select `4` (Exit). | The application displays `Exiting the program. Goodbye!` and terminates. |  |  |  |
| TC-016 | Exit after completing a transaction | Application is running | 1. Complete a successful credit or debit. 2. Select `4`. | The transaction result is displayed, then the application exits with `Exiting the program. Goodbye!`. |  |  |  |
| TC-017 | Verify the data read operation returns the stored balance | Data program is initialized with stored balance `1000.00`; an operation invokes `READ` | 1. | TC-018 | Verify the data write operation updates the stored balance | Data program is initialized; a balance value of `875.25` is available | 1. | TC-019 | Verify an unsupported data operation does not alter the stored balance | Data program stores `1000.00` | 1. Invoke the data program with an operation other than `READ` or `WRITE`. 2. The stored balance remains `1000.00`. |  |  | Confirm whether the Node.js app should reject unsupported operations explicitly. |
| TC-020 | Credit and then debit in one session | Application is running with balance `1000.00` | 1. Select `2`; enter `500.00`. 2. Select `3`; enter `125.75`. 3. Select `1`. | The credit produces `1500.00`; the debit produces `1374.25`; the final balance inquiry displays `1374.25`. |  |  |  |
| TC-021 | Validate a decimal amount with two fractional digits | Application is running with balance `1000.00` | 1. Select `2`; enter `12.34`. 2. Select `1`. | The balance increases to and displays `1012.34`. |  |  |  |
| TC-022 | Validate the COBOL numeric input limits with an oversized amount | Application is running; business stakeholders agree to test the declared numeric range | 1. Select `2` or `3`. 2. Enter an amount greater than `999999.99`. | Stakeholders observe and record the runtime behavior.
